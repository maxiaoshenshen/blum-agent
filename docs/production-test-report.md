# Blum Agent 生产环境验证报告

## 测试环境

- 执行时间：2026-08-05（Asia/Shanghai）
- 目标：`https://blum-agent-cn.maxiaoshen.chatgpt.site`
- 方法：从部署环境外部使用 `curl` 直接请求公开 URL；未携带浏览器会话、Cookie 或任何绕过访问控制的凭据。
- 判定标准：健康检查应返回 JSON；普通对话应返回约定的 JSON；流式对话应返回 `text/event-stream`；反馈应返回 JSON 成功结果；同一来源的第 31 个受限请求应由**应用**返回 `429`。

> 重要：该站点当前启用了 ChatGPT 登录保护。访问请求在站点边缘层即被拦截，未到达 Blum Agent 应用。因此本报告证明了部署可达性和访问保护行为，但不能把下列 API 的业务行为判定为通过。

### 端点详情

#### 健康检查

请求成功抵达托管站点，耗时 1.415 秒，但被访问控制层拦截。响应中的登录跳转参数为 `return_to=/api/health`，确认请求路径正确。未观察到应用健康状态字段，无法判断模型 Provider、知识库或依赖的真实健康度。

#### 普通对话

使用有效 JSON 请求体调用，耗时 0.992 秒。响应为登录页而非业务 JSON，因此无法核对回答内容、来源引用、风险等级、语言适配或模型可用性。问题本身也没有被送到模型，不能据此评估数据合理性。

#### 流式对话

初次请求出现一次 TLS `SSL_ERROR_SYSCALL`（5.007 秒）；重试后稳定返回 401（0.960 秒）及 HTML 登录页。未收到 `Content-Type: text/event-stream`、SSE 事件、`done` 事件或模型内容，故流式链路未验证。

#### 反馈接口

请求耗时 0.981 秒，返回登录页。测试数据没有写入应用反馈存储；无法验证输入校验、持久化、去重或成功响应结构。

#### 限流

按要求发送了 31 个请求。边缘访问控制在全部可达请求上先返回 401，因而应用层限流器没有机会累计计数；第 31 个请求也为 401（1.041 秒），不是预期的 429。期间 4 次 TLS 握手失败（HTTP `000`、约 5 秒），显示受保护站点的外部请求还存在间歇性连接不稳定性。

## 发现的问题

1. **P0：当前部署不满足匿名公开 API 的上线验收。** ChatGPT 登录层覆盖了所有 `/api/*` 路径，外部客户端、移动端和不带交互式登录的集成无法使用产品 API。
2. **P0：生产业务链路未被验证。** 健康检查、普通对话、SSE、反馈和应用限流均未到达应用进程；此前本地测试或构建通过不能替代本次生产验收。
3. **P1：外部 TLS 连接存在间歇失败。** 限流压测的 31 次尝试中有 4 次 `SSL_ERROR_SYSCALL`。这需要在解除访问门禁后复测，确认问题是否来自托管边缘层或连接复用。

## 上线建议与复测清单

1. 若产品应面向公众，取消部署平台对站点/API 的登录保护，或至少为 `/api/health` 和客户端所需 API 配置受控的公开访问策略。若站点设计为私有，则应明确提供服务账号 / API Gateway 认证方案，而不是依赖浏览器 ChatGPT 会话。
2. 不应把原始模型 Provider API Key 放到客户端或报告中；生产环境仅保留在服务端密钥存储，并在此前暴露过密钥时立即轮换。
3. 解除或正确配置认证后，从同一外部网络重新执行本报告中的四个端点测试，并新增以下硬性门槛：
   - `/api/health`：HTTP 200、`application/json`，且健康字段完整；
   - `/api/chat`：HTTP 200、结构正确的 JSON、回答含可核验来源且内容与 CLIP top 资料一致；
   - `/api/chat/stream`：HTTP 200、`text/event-stream`、至少一个内容事件与一个正常完成事件；
   - `/api/feedback`：HTTP 2xx、JSON 成功响应，确认测试记录的隔离与清理策略；
   - 限流：在相同身份和应用可达前提下，第 31 个请求稳定返回 HTTP 429，并带有可用的重试提示；
   - 稳定性：至少连续 100 次轻量健康请求无 TLS `000`；同时记录 P50/P95 时延。
4. 在上述复测通过前，发布状态应为“**已部署、受访问门禁保护，未完成公开生产验收**”，而非“可直接公开上线”。
